# 修改与完善记录

整理日期：2026-10-24。下列记录区分真实改动、历史诊断和待验证项。

## 本地接入期间完成的工作

1. **目标 profile 修正**：识别全局 CLI 与 DSH Desktop 内嵌 host 是两个环境。使用 Desktop 实际 `DSH_HOME`、内嵌入口、打包 pnpm shim，把插件安装到 `profiles/web`。不把全局 CLI 的安装结果冒充 Desktop 激活。
2. **固定版本**：使用 `dsh-connect-workbuddy@4.10.0` 与 Helper `v1.0.8`。本仓库保存两份标签对应的源码，未修改上游模型调用实现。
3. **桌面入口**：创建 Helper / DSH 快捷方式，设置正确的工作目录和 Helper `--data-dir`；新通用脚本用 Windows 实际 Desktop 目录，支持桌面迁移。
4. **独立账号管理**：Helper 默认监听 `127.0.0.1:18080`。服务连通性、账号数量和上游授权分开检查。
5. **一次性账号合并**：Helper 的五个国内账号曾被导入 DSH。DSH 原有两条记录加上导入记录出现七条，某些名称重复；不能据此认定新增了七个不同账号。未实施持续同步，也未擅自删除历史记录。
6. **凭据更新修复**：Helper 登录正常而 DSH 同名账号失败时，比较后确认两端凭据不同，重新导入 Helper 新凭据，历史上已恢复一个选中账号的实时积分查询。
7. **时间单位修正**：最初导入处理存在把 Helper Unix 秒当作毫秒的问题。现统一转换为 Unix 毫秒，并覆盖秒、毫秒和 ISO 时间输入测试。仅修时间字段不保证失效凭据恢复，仍需新的有效授权。
8. **视觉设置**：曾在两区域配置图片模型 ID（20 / 28），快照已去除账户信息。该操作不改变模型本身能力，不能保证文本模型突然具有视觉能力。
9. **启动诊断完善**：启动脚本保留前台输出，失败后保留窗口，避免 `start` 导致启动错误一闪而过。
10. **恢复入口完善**：支持选择自己的加密备份目录，先备份当前文件，再通过 Helper 官方按 UID 导入；备份保存在仓库之外。

## 这次上传时的通用化改动

- 去除固定 Windows 用户名、磁盘安装位置、具体手机号／昵称和特定账号 ID。
- 同步默认保留选中账号，只有显式 `-SelectAccountId` 才切换；验证该 ID 已存在。
- 仅导入 Helper 显示正常的国内账号，避免已知失效凭据覆盖；不自动重试登录、不自动签到、不启用账号池自动切换。
- DSH 只使用本机地址，从运行日志内获取认证信息，在内存里完成请求，禁止输出带 token 的地址或导出明文凭据。
- 显式使用 UTF-8 JSON，避免中文名称的 Windows PowerShell 编码问题。
- 改用公开插件接口，未移植依赖某个哈希文件名和混淆导出别名的临时诊断脚本。
- 固定上游提交／官方二进制校验，保留许可证；新增语法检查、时间单位测试和发布内容检查。

## 尚未解决或不能保证的部分

- Helper 曾出现内存中的列表为空、磁盘仍有旧加密数据的情况。最初归因为缺少 `--data-dir` 的判断不充分；后续即使指定目录也出现过。当前没有证据证明所有空列表都同因，未声称已修复上游根因。
- 受限运行器中出现 `CryptUnprotectData` 失败，只能确认该运行上下文无法解密，不能单凭此判断真实用户会话下数据损坏。
- `needs_login` 账号显示的余额可能是缓存，必须重新授权后再检查。正常显示 JWT 剩余天数也不等于上游授权有效。
- 本次整理未验证所有账号的真实模型请求；最新通用安装脚本需要在目标宿主布局上再执行验证。
- DSH 其他插件（如 dsh-purge）、内存／驱动排查与本集成无关，没有混入仓库。
