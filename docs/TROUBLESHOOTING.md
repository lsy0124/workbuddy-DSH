# 排障

## 页面显示正常，添加账号却 Failed to fetch

浏览器可保留旧页面。先查 `Invoke-RestMethod http://127.0.0.1:18080/healthz`，再看 Helper 前台启动输出。连接被拒绝表示当前没有监听服务，不是账号密码错误。若 `/healthz` 正常，查看登录接口的具体错误再判断网络或上游；不能把所有 fetch 错误都归为登录过期。

## Helper 账号列表为空

检查是否启动了不同数据目录、不同 Windows 用户或多个 Helper 实例。比较 `/api/state` 与加密备份，不要立即删账号。恢复脚本需要含 `state.bin` 的备份文件夹，且原保存用户必须能够解密它。复制 encrypted state 到另一 Windows 用户或另一电脑通常不能直接读取。

## Helper 正常，DSH 积分是横线／未登录

两端不共享内存中的登录状态。重新运行 `Sync-Accounts.ps1` 合并最新凭据；这仍是一次性同步。积分横线表示未取得结果，不等于积分为零。需要重新登录的账号不能靠设置图片开关或刷新本地列表修复。

## 同名账号重复

DSH 可能同时列出桌面发现和插件 vault 导入的记录。同名不等于同一凭据。先确认每条实际授权和来源，再决定是否在 DSH 管理页面移除旧项；本脚本保留历史记录。

## 快速状态显示 signed-in，但请求失败

`usage?detail=fast` 主要反映本地凭据。完整 `usage` 才执行选中账号的实时检查。完整积分查询成功仍不等于模型实际完成；最后用新的短对话发一个小请求验收。

## 显示没有勾选账号、批量操作无对象

这是账号池成员未选择的问题，不是所有账号都消失。按需在插件设置里选择并保存成员；本仓库不会自动启用账号池和签到任务。

## 模型不支持图片

模型选择弹窗不是图片能力设置位置。插件设置的 `imageModelIds` 决定附件路由资格；只填实际支持图片的模型 ID。上游不支持的模型无法靠开关增加能力。

## 插件安装了但 Desktop 看不到

检查 `%APPDATA%\dsh-desktop\harness\profiles\web`、实际 Desktop 的启动日志和插件版本，再重启 Desktop。全局 npm 的 `dsh` 版本／profile 与 Desktop 内嵌 host 可能不同。

## 提交问题时

只附错误摘要、组件版本、端口是否监听和不含身份的数量。不要上传 state.bin、vault、完整启动日志、认证 URL、截图里的账号资料或 token。
